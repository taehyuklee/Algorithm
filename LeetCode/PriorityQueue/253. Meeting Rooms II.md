# Meeting Rooms II — 내 사고와 정석 사고의 차이

## 내가 처음 잡은 방향

처음에는 다음과 같이 생각했다.

```text
1. 회의를 시작 시간 순으로 정렬한다.
2. rooms에 현재 사용 중인 방들을 저장한다.
3. 새로운 회의가 들어오면 기존 room들을 하나씩 확인한다.
4. 기존 회의와 겹치면 새로운 방을 만든다.
5. 겹치지 않으면 기존 방을 사용할 수 있다.
```

초기 코드의 핵심은 이런 형태였다.

```python
for room in rooms:
    old_start, old_end = room

    if new_start < old_end:
        rooms.append([new_start, new_end])
        cnt_room += 1
```

큰 방향에서

```text
회의 시간 비교
→ 겹치면 추가 room 필요
→ 안 겹치면 room 재사용
```

이라는 생각은 맞았다.

---

# 문제점 1 — 모든 방과 겹치는지를 확인할 필요가 없었다

예를 들어 현재 방들이:

```text
Room A → [0, 30]
Room B → [5, 10]
```

이고 새로운 회의가:

```text
[15, 20]
```

이라고 하자.

Room A와 비교하면:

```text
15 < 30

→ 겹침
```

그래서 처음 내 사고대로라면:

```text
새로운 방이 필요하겠네?
```

라고 판단할 수 있다.

하지만 Room B를 보면:

```text
10 <= 15
```

이므로 이미 10시에 끝났고 재사용할 수 있다.

즉:

```text
"어떤 방과 겹치는가?"
```

를 확인하는 것이 중요한 것이 아니었다.

진짜 질문은:

```text
"사용 가능한 방이 하나라도 있는가?"
```

이다.

---

# 문제점 2 — 가장 빨리 끝나는 방 하나만 보면 된다

현재 방들의 종료 시간이:

```python
rooms = [
    [0, 30],
    [5, 10],
    [8, 25]
]
```

라고 하자.

종료시간만 보면:

```text
30
10
25
```

가장 빨리 끝나는 방은:

```text
10
```

이다.

새로운 회의가:

```text
[15, 20]
```

이면

```text
10 <= 15
```

이므로 10시에 끝나는 방을 재사용하면 된다.

반대로 새로운 회의가:

```text
[7, 20]
```

이면:

```text
10 <= 7
```

False.

그런데 `10`이 **모든 방 중 가장 빨리 끝나는 시간**이다.

가장 빨리 끝나는 방조차 7시까지 비지 않았다면:

```text
10 > 7
25 > 7
30 > 7
```

나머지 방도 당연히 전부 사용할 수 없다.

따라서:

```text
가장 빨리 끝나는 방 하나만 확인하면 된다.
```

# 내 사고의 변화

처음:

```text
새 회의
↓
모든 방을 확인
↓
어떤 방과 겹치는지 검사
↓
겹치면 방 추가
```

수정:

```text
새 회의
↓
가장 빨리 끝나는 방을 찾음
↓
그 방의 end <= 새 회의 start ?
       /                 \
     Yes                  No
      ↓                    ↓
기존 방 재사용           새 방 생성
```

# 문제점 3 — 방을 재사용하면 종료시간을 교체해야 한다

예를 들어:

```text
Room A → 10시에 끝남
```

새로운 회의:

```text
[15, 20]
```

`10 <= 15`이므로 Room A를 재사용할 수 있다.

하지만 이제 Room A는 더 이상:

```text
10시에 끝나는 방
```

이 아니다.

새로운 회의가 배정되었으므로:

```text
20시에 끝나는 방
```

이 된다.

따라서:

```text
기존
rooms = [30, 10]
```

이라면 Room을 재사용한 후:

```text
rooms = [30, 20]
```

으로 바꿔줘야 한다.

즉:

```text
방 재사용
→ 기존 종료시간 제거
→ 새 회의 종료시간으로 교체
```

가 필요하다.

---

# 내가 만든 방식대로 구현한다면

Interval 전체를 room으로 가지고 있을 수도 있다.

```python
class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:

        # 회의 시작시간 기준 정렬
        intervals.sort(key=lambda x: x[0])

        rooms = []

        for new_start, new_end in intervals:

            # 첫 번째 회의
            if len(rooms) == 0:
                rooms.append([new_start, new_end])
                continue

            # 종료시간을 기준으로 방 정렬
            sorted_rooms = sorted(
                rooms,
                key=lambda x: x[1]
            )

            # 가장 빨리 끝나는 방
            earliest_room = sorted_rooms[0]

            old_start = earliest_room[0]
            old_end = earliest_room[1]

            # 기존 방 재사용 가능
            if old_end <= new_start:

                # rooms에서 해당 room 위치를 찾음
                room_idx = rooms.index(earliest_room)

                # 새로운 회의로 교체
                rooms[room_idx] = [new_start, new_end]

            # 기존 방을 하나도 사용할 수 없음
            else:
                rooms.append([new_start, new_end])

        return len(rooms)
```

```python
intervals = [
```

```python
rooms = [
```

## 세 번째 `[15,20]`

종료시간 순으로 정렬하면:

```python

    [5,10],
    [0,30]
]
```

가장 빨리 끝나는 방:

```text
[5,10]
```

비교:

```text
10 <= 15 ?
True
```

```python
rooms = [
    [0,30],
```

```python
rooms = [
```

```python
len(rooms) == 2
```

```text
2
```

# `sorted()` 사용 시 주의

이 코드는 가능하다.

```python
sorted_rooms = sorted(
    rooms,
    key=lambda x: x[1]
)
```

두 번째 원소인 `end`를 기준으로 정렬한다.

예:

```python
rooms = [
    [0,30],
    [5,10],
    [8,20]
]
```

결과:

```python
sorted_rooms = [
    [5,10],
    [8,20],
    [0,30]
]
```

따라서:

```python
sorted_rooms[0]
```

이 가장 빨리 끝나는 방이다.

단,

```python
sorted_rooms = sorted(...)
```

는 **새로운 리스트를 만드는 것**이므로 `rooms` 자체의 순서는 바뀌지 않는다.

원본 자체를 정렬하고 싶다면:

```python
rooms.sort(key=lambda x: x[1])
```

을 사용한다.

# 내 사고와 정석 풀이의 핵심 차이

| 항목 | 처음 내 사고 | 수정된 사고 |
|---|---|---|
| 회의 정렬 | 시작시간 기준 | 시작시간 기준 |
| Room 관리 | 모든 room과 비교 | 가장 빨리 끝나는 room 확인 |
| 판단 질문 | 이 room과 겹치는가? | 재사용 가능한 room이 있는가? |
| 비교 대상 | 여러 room | minimum end time |
| 재사용 시 | 상태 관리 부족 | 기존 room의 end 갱신 |
| 새 방 생성 | 겹치는 room 발견 시 | 가장 빠른 room조차 사용 불가능할 때 |

# 가장 중요한 사고의 전환

처음에는:

```text
"새로운 회의가 기존 회의와 겹치는가?"
```

를 중심으로 생각했다.

하지만 Meeting Rooms II에서 진짜 필요한 질문은:

```text
"현재 존재하는 방 중
새로운 회의가 사용할 수 있는 방이 있는가?"
```

이다.

그리고 그걸 판단하기 위해서는:

```text
모든 방 중 가장 빨리 끝나는 방
```

만 보면 된다.

---

# 여기서 Heap으로 연결되는 이유

현재 내 방식에서는 매번:

```python
sorted_rooms = sorted(
    rooms,
    key=lambda x: x[1]
)
```

해서 가장 빨리 끝나는 방을 찾는다.

즉 내가 실제로 원하는 연산은 계속 이것이다.

```text
"현재 방 중 최소 end를 빠르게 꺼내고 싶다."
```

이런 연산을 잘하는 자료구조가:

```text
Min Heap
```

이다.

그래서 정석 풀이가 갑자기 Heap을 사용하는 것이 아니라,

```text
내 풀이
↓
가장 빨리 끝나는 방 필요
↓
매번 sort하면 비효율적
↓
minimum을 계속 빠르게 찾고 싶음
↓
Min Heap
```

으로 자연스럽게 발전하는 것이다.

# 내 사고 한 줄 정리

> 처음에는 각 방과의 overlap을 검사하려고 했지만, 실제로는 모든 방 중 가장 빨리 끝나는 방 하나만 확인하면 된다. 그 방이 새 회의 시작 전에 끝났다면 해당 방의 종료시간을 새 회의 종료시간으로 교체하고, 그 방조차 끝나지 않았다면 새로운 방을 추가한다.

## 문제를 다시 봤을 때 사고 흐름

```text
Meeting Rooms II
↓
회의를 start 기준으로 정렬
↓
현재 사용 중인 room들의 종료시간 관리
↓
가장 빨리 끝나는 room 확인
↓
earliest_end <= new_start ?
       /                 \
     Yes                  No
      ↓                    ↓
room 재사용              새 room 추가
      ↓
종료시간을 new_end로 갱신
↓
최종 room 개수
```

이 흐름이 먼저 자연스럽게 나오면 되고,
그다음 최적화 단계에서 `Min Heap`으로 바꾸면 된다.
