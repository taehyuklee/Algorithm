# Binary Tree DFS / Recursion — 내가 실수했던 부분 정리

## 1. `global`과 `nonlocal` 구분

함수 안에 또 다른 함수가 있고, 바깥 함수의 변수를 내부 함수에서 수정하려면 `global`이 아니라 `nonlocal`을 사용해야 한다.

```python
def maxDepth(root):
    max_depth = 0

    def dfs(root, depth):
        nonlocal max_depth
        max_depth = max(max_depth, depth)
```

### 이유

`max_depth`는 Python 파일 전체의 전역 변수가 아니라 `maxDepth()` 함수의 지역 변수다.

```text
module
└── maxDepth()
      ├── max_depth
      └── dfs()
            ↑
            바깥 함수의 max_depth를 수정
```

따라서:

```python
nonlocal max_depth
```

를 사용한다.

### 기억

```text
global
→ 모듈 전체의 전역 변수

nonlocal
→ 바깥 함수의 지역 변수
```

# 2. `return`을 너무 일찍 하면 sibling을 탐색하지 못한다

처음 작성했던 형태:

```python
if root.left is None:
    return

if root.right is not None:
    dfs(root.right)
```

이렇게 하면 왼쪽 자식이 없는 순간 **현재 함수 자체가 종료된다.**

예:

```text
1
 \
  2
   \
    3
```

`1.left == None`이므로:

```python
return
```

해버리면 오른쪽 `2`, `3`을 전혀 탐색하지 못한다.

따라서:

```python
if root.left is not None:
    dfs(root.left)

if root.right is not None:
    dfs(root.right)
```

처럼 작성하는 것이 좋다.

---

# 3. `depth += 1`을 직접 하면 backtracking이 필요하다

처음 생각한 방식:

```python
depth += 1
dfs(root.left, depth)

depth += 1
dfs(root.right, depth)
```

문제는 `depth += 1`이 **현재 함수 프레임의 depth 자체를 변경한다는 것**이다.

예:

```text
        3       depth = 1
       / \
      9   20
```

왼쪽으로 이동:

```text
3의 depth = 1

depth += 1
→ depth = 2

9 탐색
```

`9` 탐색이 끝나 다시 `3`으로 돌아와도 현재 함수의 `depth`는 여전히 `2`다.

그 상태에서:

```python
depth += 1
```

하면:

```text
20의 depth = 3
```

이 되어버린다.

하지만 `9`와 `20`은 같은 level이므로 둘 다 depth `2`여야 한다.

따라서 직접 `+= 1` 했다면:

```python
depth += 1
dfs(root.left, depth)

depth -= 1  # backtracking

depth += 1
dfs(root.right, depth)

depth -= 1
```

처럼 원래 상태로 되돌려야 한다.

---

# 4. 더 간단한 방법: `depth + 1`을 인자로 넘긴다

직접:

```python
depth += 1
```

하지 않고:

```python
dfs(root.left, depth + 1)
dfs(root.right, depth + 1)
```

처럼 넘기면 backtracking이 필요 없다.

예:

```text
현재 함수:
depth = 1

왼쪽 호출:
depth + 1 → 2

왼쪽 호출 종료

현재 함수:
depth = 여전히 1

오른쪽 호출:
depth + 1 → 2
```

따라서:

```python
depth -= 1
```

을 할 필요가 없다.

### 핵심

```text
depth += 1
→ 현재 함수의 상태를 직접 변경
→ 다시 복구해야 함

depth + 1
→ 자식 함수에게 새로운 값을 전달
→ 현재 함수의 depth는 그대로
```

# 5. 재귀 함수의 `return`을 빼먹으면 `None`이 반환된다

Python 함수는 명시적인 `return` 없이 끝나면:

```python
return None
```

과 동일하다.

예:

```python
def dfs(root):
    dfs(root.left)
```

이 함수는 재귀 호출을 하긴 하지만 결과를 반환하지 않는다.

따라서:

```python
left_depth = dfs(root.left)
```

하면:

```text
left_depth = None
```

이 될 수 있다.

그 상태에서:

```python
max(left_depth, right_depth)
```

를 하면:

```text
TypeError:
'>' not supported between instances of 'NoneType' and 'NoneType'
```

같은 오류가 발생한다.

따라서 재귀 결과를 이용하는 방식이라면:

```python
left_depth = dfs(root.left)
right_depth = dfs(root.right)

return max(left_depth, right_depth)
```

처럼 **재귀 결과를 반드시 return으로 위로 전달해야 한다.**

# 6. 조건문 안에서 만든 변수는 조건이 False면 존재하지 않을 수 있다

예:

```python
if root.left is not None:
    left_depth = dfs(root.left)

if root.right is not None:
    right_depth = dfs(root.right)

return max(left_depth, right_depth)
```

만약 `root.left`가 `None`이면:

```python
left_depth = ...
```

이 실행되지 않는다.

그러면 마지막:

```python
return max(left_depth, right_depth)
```

에서:

```text
UnboundLocalError:
cannot access local variable 'left_depth'
where it is not associated with a value
```

가 발생한다.

즉 모든 실행 경로에서 변수에 값이 들어가도록 해야 한다.

예:

```python
if root.left is not None:
    left_depth = dfs(root.left)
else:
    left_depth = depth
```

또는 더 좋은 방법으로 `None` 자체를 재귀 함수의 종료조건으로 처리할 수 있다.

---

# 7. 빈 트리(`root is None`)를 반드시 처리한다

Maximum Depth 문제에서:

```text
root = None
```

이면 깊이는 `0`이다.

따라서:

```python
if root is None:
    return 0
```

이 필요하다.

그렇지 않고 바로:

```python
root.left
```

에 접근하면 오류가 발생할 수 있다.

---

# 8. 재귀 함수를 정의만 하고 호출하지 않는 실수

이렇게:

```python
def dfs(root, depth):
    ...
```

함수를 정의해놓고 마지막에:

```python
return max_depth
```

만 하면 DFS는 한 번도 실행되지 않는다.

반드시 시작점에서 호출해야 한다.

```python
dfs(root, 1)

return max_depth
```

# 9. `nonlocal` 없이 풀고 싶다면 결과를 return한다

외부의:

```python
max_depth
```

를 수정하지 않고, 각 재귀 함수가 자신의 결과를 반환하도록 만들 수 있다.

예:

```python
def dfs(root, depth):

    if root is None:
        return depth

    left_depth = dfs(root.left, depth + 1)
    right_depth = dfs(root.right, depth + 1)

    return max(left_depth, right_depth)
```

이렇게 하면:

```text
자식이 계산한 depth
↓
부모에게 return
↓
부모가 max() 계산
↓
다시 위로 return
```

하는 구조가 된다.

# 10. 가장 정석적인 Maximum Depth 사고

이 문제는 사실 현재 depth를 직접 들고 다니지 않아도 된다.

현재 노드의 최대 깊이는:

```text
왼쪽 subtree의 최대 깊이
오른쪽 subtree의 최대 깊이

둘 중 큰 값 + 현재 노드 1개
```

이다.

따라서:

```python
def maxDepth(root):

    if root is None:
        return 0

    left_depth = maxDepth(root.left)
    right_depth = maxDepth(root.right)

    return max(left_depth, right_depth) + 1
```

# 내가 이번 문제에서 실수했던 핵심 요약

```text
1. 바깥 함수 변수를 수정하면서 global을 사용하려 했다.
   → nonlocal 사용

2. left가 None이면 return 해버렸다.
   → 오른쪽 subtree 탐색까지 종료됨

3. depth += 1로 현재 depth를 변경했다.
   → sibling 탐색 전에 depth -= 1 필요

4. depth + 1을 인자로 넘기면
   → backtracking으로 -1 할 필요 없음

5. 재귀 호출 결과를 return하지 않았다.
   → Python은 None 반환

6. 조건문 안에서만 left_depth/right_depth를 생성했다.
   → 조건이 False면 변수가 존재하지 않을 수 있음

7. root=None 처리가 필요하다.
   → 빈 트리 depth = 0

8. 내부 DFS 함수를 정의하고 실제 호출을 빼먹었다.

9. 외부 상태(max_depth)를 사용하지 않으려면
   → 재귀 결과를 return하여 부모가 계산하게 한다.
```

# 가장 기억해야 할 재귀/DFS 감각

```text
DFS에서 내려갈 때 상태를 직접 변경했다면
→ 돌아올 때 상태 복구(backtracking)가 필요할 수 있다.

하지만

dfs(child, depth + 1)

처럼 새로운 값을 인자로 전달하면
→ 부모 함수의 depth는 바뀌지 않는다.
→ 별도의 depth -= 1이 필요 없다.
```

그리고 재귀에서 값을 계산하는 문제라면:

```text
자식 함수가 계산
→ return
→ 부모가 결과를 받음
→ 부모가 다시 계산
→ return
```

이라는 흐름을 항상 의식한다.
