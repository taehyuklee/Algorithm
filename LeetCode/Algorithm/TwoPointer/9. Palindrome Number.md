# Palindrome 문제 — 알고리즘 분류 정리

## 핵심

Palindrome 문제라고 해서 모두 같은 알고리즘을 사용하는 것은 아니다.

문제가 요구하는 것이:

```text
부분 문자열에서 Palindrome을 찾는 것인지

vs

전체 문자열/숫자가 Palindrome인지 확인하는 것인지
```

에 따라 접근이 달라진다.

---

# 1. Palindrome Number

LeetCode 9. **Palindrome Number**

예:

```text
Input: 121
Output: True
```

이 문제의 질문은:

> **숫자 전체가 Palindrome인가?**

이다.

부분적으로 Palindrome이 존재하는지는 중요하지 않다.

---

## 알고리즘 분류

```text
자료형 / 대상:
Integer → String

알고리즘:
Two Pointers

시간복잡도:
O(N)

공간복잡도:
O(N)  # 문자열로 변환하는 경우
```

핵심 알고리즘은 **Two Pointers**다.

---

# 2. Two Pointers로 생각하는 이유

문자열의 양끝에서 시작한다.

예:

```text
1 2 3 2 1
↑       ↑
L       R
```

비교:

```text
1 == 1
```

그러면 안쪽으로 이동한다.

```text
1 2 3 2 1
  ↑   ↑
  L   R
```

다시:

```text
2 == 2
```

안쪽으로 이동:

```text
1 2 3 2 1
    ↑
   L,R
```

끝까지 모두 같으면:

```text
Palindrome
```

---

## 코드

```python
class Solution:
    def isPalindrome(self, x: int) -> bool:

        if x < 0:
            return False

        s = str(x)

        l = 0
        r = len(s) - 1

        while l < r:

            if s[l] != s[r]:
                return False

            l += 1
            r -= 1

        return True
```

# 3. Longest Palindromic Substring

LeetCode 5. **Longest Palindromic Substring**

예:

```text
Input:
"babad"

Output:
"bab"
```

또는:

```text
"aba"
```

이 문제는 전체 문자열이 Palindrome인지 묻는 게 아니다.

질문은:

> **문자열 안에 존재하는 Palindrome Substring 중 가장 긴 것은 무엇인가?**

이다.

---

## 알고리즘 분류

```text
자료형 / 대상:
String

알고리즘:
Expand Around Center

넓게 보면:
Two Pointers 계열

시간복잡도:
O(N²)

공간복잡도:
O(1)
# 결과 substring 저장 비용 등은 별도
```

---

# 4. Expand Around Center

Palindrome은 중심을 기준으로 좌우가 대칭이다.

그래서 중심에서 시작해서 양쪽으로 확장한다.

---

## Odd Case

예:

```text
a b a
  ↑
center
```

시작:

```python
l = i
r = i
```

처음:

```text
a b a
  ↑
 l=r
```

`b` 하나도 Palindrome이다.

그다음:

```text
a b a
↑   ↑
l   r
```

`a == a`

따라서:

```text
"aba"
```

도 Palindrome이다.

---

# 5. Even Case

예:

```text
a b b a
  ↑ ↑
  L R
```

짝수 길이 Palindrome은 가운데 문자가 하나 존재하지 않는다.

따라서 시작점을:

```python
l = i
r = i + 1
```

로 잡는다.

처음:

```text
a b b a
  ↑ ↑
```

```text
b == b
```

확장:

```text
a b b a
↑     ↑
```

```text
a == a
```

따라서:

```text
"abba"
```

가 Palindrome이다.

# 6. 두 문제의 결정적인 차이

## Palindrome Number

질문:

```text
전체가 Palindrome인가?
```

따라서:

```text
양끝에서 시작
↓
안쪽으로 이동
```

즉:

```text
Two Pointers
```

---

## Longest Palindromic Substring

질문:

```text
Palindrome이 어디에 숨어 있는가?
```

따라서 가능한 중심들을 하나씩 검사한다.

```text
각 i를 중심으로 잡음
↓
좌우로 확장
```

즉:

```text
Expand Around Center
```

# 7. 내가 헷갈렸던 부분

Longest Palindromic Substring에서는:

```text
부분 Palindrome을 발견
```

하는 것이 중요했다.

예:

```text
b a b a d
↑   ↑

"bab"
```

전체 `"babad"`가 Palindrome이 아니어도 상관없다.

---

그런데 Palindrome Number에서:

```text
1 2 1
↑
```

`"1"` 하나가 Palindrome이라고 해서:

```text
121 전체가 Palindrome이다
```

라고 바로 판단하면 안 된다.

`"1"`이 Palindrome인 것은 맞지만 **부분 Palindrome일 뿐**이다.

Palindrome Number에서는 반드시:

```text
전체 길이
```

가 Palindrome이어야 한다.

---

# 8. 한 글자도 Palindrome인가?

맞다.

```text
"a"
"1"
"7"
```

모두 Palindrome이다.

왜냐하면 앞에서 읽어도 뒤에서 읽어도 같기 때문이다.

따라서:

```text
x = 7
```

이면:

```text
True
```

다.

하지만:

```text
x = 123
```

에서 `"1"` 하나가 Palindrome이라고 해서 `123`이 Palindrome인 것은 아니다.

핵심은:

```text
부분이 Palindrome인가?

vs

전체가 Palindrome인가?
```

를 구분하는 것이다.

---

# 9. 알고리즘 분류 정리

| 문제 | 분류 | 핵심 알고리즘 |
|---|---|---|
| Palindrome Number | String / Two Pointers | 양끝 → 안쪽 |
| Valid Palindrome | String / Two Pointers | 양끝 → 안쪽 |
| Longest Palindromic Substring | String | Expand Around Center |
| Palindromic Substrings | String | Expand Around Center |

---

# 10. 방향으로 기억하기

## Two Pointers

```text
밖 → 안
```

예:

```text
1 2 3 2 1
↑       ↑
 →     ←
```

이미 **전체 범위가 정해져 있고**, 그 전체가 조건을 만족하는지 검사한다.

---

## Expand Around Center

```text
안 → 밖
```

예:

```text
1 2 3 2 1
    ↑
   중심

    ↓

1 2 3 2 1
  ↑   ↑

    ↓

1 2 3 2 1
↑       ↑
```

어디까지 Palindrome이 되는지 **범위를 찾아가는 것**이다.

---
