# Merge Intervals — 내 실수 정리

## 문제 핵심

Interval들이 주어졌을 때 서로 겹치는 구간들을 합치는 문제.

예:

```python
intervals = [[1,3], [2,6], [8,10], [15,18]]
```

정답:

```python
[[1,6], [8,10], [15,18]]
```

---

## 사고 흐름

1. 시작점을 기준으로 정렬
2. 현재까지 merge된 마지막 interval과 다음 interval 비교
3. 겹치면 merge
4. 안 겹치면 새 interval 추가

즉:

```text
Sort
↓
현재 answer의 마지막 interval 확인
↓
old_end >= next_start ?
   /          \
 Yes          No
  ↓            ↓
Merge       Append
```

---

## 내가 최종적으로 푼 코드

```python
class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        # 우선 시작점을 정렬하고 끝점과 다음 시작점을 비교해가면서
        # 겹치는 부분을 봅니다.

        # O(N log N)
        intervals.sort(key=lambda x: x[0])

        # Initial
        start_p = intervals[0][0]
        end_p = intervals[0][1]

        answer_list = [[start_p, end_p]]

        for i in range(1, len(intervals)):

            # 현재까지 merge된 마지막 interval
            old_s, old_e = answer_list[-1]

            next_s = intervals[i][0]
            next_e = intervals[i][1]

            # 기존 interval의 end가
            # 다음 interval의 start보다 크거나 같으면 겹침
            if old_e >= next_s:

                new_s = old_s
                new_e = max(old_e, next_e)

                # 기존 interval을 제거하고
                answer_list.pop()

                # merge된 interval을 다시 추가
                answer_list.append([new_s, new_e])

            else:
                # 겹치지 않으면 새로운 interval 추가
                answer_list.append([next_s, next_e])

        return answer_list
```

# 내가 처음에 했던 실수

처음 코드에서는 다음과 같이 별도의 상태를 가지고 있었다.

```python
start_p = intervals[0][0]
end_p = intervals[0][1]
```

그리고 겹치면:

```python
new_s = start_p
new_e = max(end_p, next_e)

answer_list.append([new_s, new_e])
```

라고 했다.

문제는 `new_e`를 계산하고도 기존 상태인 `end_p`를 갱신하지 않았다는 것.

예:

```python
intervals = [[1,3], [2,6], [5,8]]
```

첫 번째 merge:

```text
[1,3] + [2,6]

→ [1,6]
```

그런데 기존 코드에서는:

```text
start_p = 1
end_p = 3
```

가 그대로 남아 있었다.

그래서 다음 `[5,8]`과 비교할 때:

```python
3 >= 5
```

를 검사하게 됨.

하지만 실제 비교해야 하는 것은:

```python
6 >= 5
```

이다.

즉 현재까지 merge된 최신 interval을 기준으로 계속 비교해야 한다.

---

# 내가 수정한 방식

현재까지 merge된 결과가 이미:

```python
answer_list[-1]
```

에 들어 있으므로 별도로 `start_p`, `end_p`를 계속 관리하지 않고,

```python
old_s, old_e = answer_list[-1]
```

로 가장 최근 merge 결과를 가져온다.

예:

```python
answer_list = [[1,6]]
```

이면:

```python
old_s, old_e = answer_list[-1]

# old_s = 1
# old_e = 6
```

따라서 다음 `[5,8]`이 들어오면:

```python
old_e >= next_s

6 >= 5
```

가 되어 정상적으로 겹침을 판단할 수 있다.

True → 겹침

```

answer_list = [[1,8]]
```

# 핵심 조건

두 interval이 있을 때:

```text
[old_s, old_e]
[next_s, next_e]
```

겹치는 조건:

```python
old_e >= next_s
```

즉:

```text
기존 구간의 끝점 >= 다음 구간의 시작점
```

이면 겹친다.

예:

```text
[1-------6]
       [5-------8]

6 >= 5
```

따라서:

```text
[1-----------8]
```

로 merge.

---

겹치지 않는 경우:

```text
[1----3]

          [5----8]
```

조건:

```python
3 >= 5
```

False

따라서 별개의 interval로 추가한다.

---

# 왜 먼저 정렬해야 하는가?

시작점을 기준으로 정렬하면:

```text
[1,3]
[2,6]
[5,8]
[10,12]
```

항상 왼쪽에서 오른쪽으로 진행하게 된다.

따라서 이전의 모든 interval을 다시 비교할 필요 없이:

```python
answer_list[-1]
```

즉 **현재까지 merge된 마지막 interval만 다음 interval과 비교**하면 된다.

이게 이 문제의 핵심이다.

---

# 더 간단하게 작성할 수도 있음

현재 코드에서:

```python
answer_list.pop()
answer_list.append([new_s, new_e])
```

를 굳이 할 필요 없이 리스트의 마지막 값을 직접 수정할 수도 있다.

```python
class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:

        intervals.sort(key=lambda x: x[0])

        answer_list = [intervals[0]]

        for i in range(1, len(intervals)):

            old_s, old_e = answer_list[-1]
            next_s, next_e = intervals[i]

            if old_e >= next_s:
                answer_list[-1][1] = max(old_e, next_e)

            else:
                answer_list.append([next_s, next_e])

        return answer_list
```

핵심은 동일하다.

```text
겹침
→ answer_list[-1]을 확장

안 겹침
→ 새로운 interval append
```

---

# Complexity

정렬:

```text
O(N log N)
```

전체 interval 한 번 순회:

```text
O(N)
```

따라서 전체:

```text
Time Complexity: O(N log N)
```

결과 리스트를 저장하므로:

```text
Space Complexity: O(N)
```

Python의 sort 자체가 사용하는 추가 공간은 구현 관점에서 별도로 고려할 수 있지만,
면접에서는 보통 결과 배열 기준으로 `O(N)`이라고 설명하면 된다.

# 이 문제를 봤을 때 바로 나와야 하는 사고

```text
Merge Intervals
↓
구간 문제
↓
시작점 기준 Sort
↓
현재까지 merge된 마지막 interval만 확인
↓
old_end >= next_start ?
↓
Yes → end = max(old_end, next_end)
No  → 새로운 interval append
↓
O(N log N)
```

## 내 실수 한 줄 요약

> Merge된 새로운 구간을 만들었는데, 다음 비교에서도 최신 merge 결과를 사용해야 한다는 상태 관리가 빠져 있었다.

수정 후에는:

> `answer_list[-1]`을 항상 현재까지 merge된 최신 interval로 사용한다.
