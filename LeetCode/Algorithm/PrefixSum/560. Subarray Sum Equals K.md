# Subarray Sum Equals K — 내가 착각했던 부분

## 내가 처음 생각했던 것

나는 현재 위치까지 왔을 때, 현재 누적합을 먼저 HashMap에 넣어야 현재 원소까지 포함된 subarray를 셀 수 있다고 생각했다.

즉 이런 순서를 생각했다.

```python
culcum_sum += nums[i]

# 현재 누적합 먼저 저장
culcum_hash[culcum_sum] = culcum_hash.get(culcum_sum, 0) + 1

# 그 다음 필요한 과거 prefix 탐색
prefix_p = culcum_sum - k

if prefix_p in culcum_hash:
    answer += culcum_hash[prefix_p]
```

내 생각은:

> 현재 누적합을 먼저 저장하지 않으면 마지막 원소까지 포함된 subarray가 반영되지 않을 것 같다.

였다.

---

## 실제로는

현재 원소는 이미 이 코드에서 누적합에 반영된다.

```python
culcum_sum += nums[i]
```

즉 현재 index가 `i`라면 `culcum_sum`은 이미:

```text
nums[0] + nums[1] + ... + nums[i]
```

를 의미한다.

따라서 현재 원소까지 포함된 상태는 이미 만들어져 있다.

HashMap에 현재 누적합을 먼저 저장할 필요가 없다.

---

## 예시

```text
nums = [1, 2]
k = 3
```

두 번째 원소 `2`까지 왔다고 하자.

```python
culcum_sum += nums[i]
```

를 실행하면:

```text
culcum_sum = 1 + 2 = 3
```

즉 `[1, 2]` 전체가 이미 현재 누적합에 반영되어 있다.

이제 필요한 과거 prefix는:

```text
current_sum - previous_prefix = k
```

이므로:

```text
previous_prefix = current_sum - k
```

대입하면:

```text
previous_prefix = 3 - 3 = 0
```

초기 HashMap에는:

```python
culcum_hash = {0: 1}
```

이 있으므로:

```text
현재 누적합 3
-
과거 누적합 0
=
3
```

이 되어 `[1, 2]`를 정상적으로 찾을 수 있다.

즉 마지막 원소 `2`까지 이미 반영되어 있다.

---

# 핵심 역할 구분

현재 위치에서:

```text
current_sum
→ 현재 index까지의 누적합
→ 현재 원소까지 이미 포함됨
```

HashMap은:

```text
과거에 등장했던 prefix sum들의 기록
```

이다.

따라서 역할은 다음과 같다.

```text
현재 = current_sum

과거 = HashMap
```

그리고:

```text
현재 누적합 - 과거 누적합 = k
```

가 되는 과거 prefix를 찾는 것이다.

---

# 그래서 순서가 중요하다

올바른 순서:

```python
culcum_sum += nums[i]

prefix_p = culcum_sum - k

# 1. 과거 prefix에서 먼저 찾는다.
if prefix_p in culcum_hash:
    answer += culcum_hash[prefix_p]

# 2. 현재 prefix는 그 다음 저장한다.
culcum_hash[culcum_sum] = culcum_hash.get(culcum_sum, 0) + 1
```

즉:

```text
현재 원소 누적합에 반영
        ↓
과거 prefix 탐색
        ↓
정답 계산
        ↓
현재 prefix 저장
        ↓
다음 index에서는 현재 prefix가 "과거"가 됨
```

---

# 왜 현재 prefix를 먼저 저장하면 안 되는가?

현재 prefix를 먼저 저장하면 자기 자신을 과거 prefix처럼 사용할 수 있다.

특히 `k = 0`일 때 문제가 생긴다.

예:

```text
nums = [1, -1]
k = 0
```

첫 번째 원소 `1`에서:

```text
current_sum = 1
prefix_p = 1 - 0 = 1
```

만약 현재 `1`을 HashMap에 먼저 넣으면:

```text
HashMap에 prefix 1 존재
```

라고 판단해버린다.

그러면:

```text
현재 prefix 1 - 현재 prefix 1 = 0
```

을 하나의 subarray로 세게 된다.

하지만 이는 실제로:

```text
[]
```

와 같은 길이 0짜리 구간을 센 것과 같다.

따라서 현재 prefix를 탐색 전에 넣으면 안 된다.

---

# 내가 착각했던 핵심

```text
잘못 생각한 것:

"현재 prefix를 HashMap에 먼저 넣어야
현재 원소까지 포함된 경우가 반영된다."
```

하지만 실제로는:

```text
culcum_sum += nums[i]
```

이 실행되는 순간 이미 현재 원소까지 모두 반영되어 있다.

HashMap은 현재를 표현하기 위한 것이 아니라:

```text
현재 누적합에서 빼줄 과거 prefix를 찾기 위한 저장소
```

이다.

---

# 한 줄 정리

> 현재 원소는 이미 `current_sum`에 들어 있고, HashMap에는 과거 prefix만 있어야 한다.

따라서 항상:

```text
찾고 → 저장
```

순서로 진행한다.

```python
culcum_sum += nums[i]

prefix_p = culcum_sum - k

if prefix_p in culcum_hash:
    answer += culcum_hash[prefix_p]

culcum_hash[culcum_sum] = culcum_hash.get(culcum_sum, 0) + 1
```
