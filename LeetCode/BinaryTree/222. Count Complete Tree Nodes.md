# Count Complete Tree Nodes — 두 가지 O(log² N) 접근 정리

LeetCode 222. **Count Complete Tree Nodes**

이 문제의 핵심 조건은 **Complete Binary Tree**라는 점이다.

Complete Binary Tree는:

- 마지막 레벨을 제외한 모든 레벨이 꽉 차 있다.
- 마지막 레벨은 **왼쪽부터 순서대로** 채워진다.

이 성질 덕분에 모든 노드를 하나씩 세는 `O(N)`보다 빠르게 노드 개수를 구할 수 있다.

---

# 1. 방식 A — 현재 Subtree 전체가 Perfect인지 확인

## 핵심 아이디어

내가 처음 생각한 방식.

현재 subtree를 하나의 트리라고 생각하고:

```text
현재 subtree의 맨 왼쪽 높이
vs
현재 subtree의 맨 오른쪽 높이
```

를 비교한다.

높이가 같으면:

```text
left height == right height
        ↓
현재 subtree 전체가 Perfect Binary Tree
        ↓
더 이상 재귀하지 않고 노드 수를 한 번에 계산
```

높이가 다르면:

```text
현재 subtree는 perfect가 아님
        ↓
왼쪽 subtree 재귀
오른쪽 subtree 재귀
```

---

## Perfect Tree 예시

```text
        1
      /   \
     2     3
    / \   / \
   4   5 6   7
```

맨 왼쪽:

```text
1 → 2 → 4
```

맨 오른쪽:

```text
1 → 3 → 7
```

둘의 높이가 같다.

따라서 현재 트리 전체가 Perfect Binary Tree.

노드 개수는:

```text
2^0 + 2^1 + 2^2

= 1 + 2 + 4

= 7
```

---

# 2. Summation으로 Perfect Tree 노드 수 구하기

공식이 기억나면:

```text
2^height - 1
```

하지만 공식을 까먹었다면 그냥 직접 더해도 된다.

```python
def summation_nodes(height):
    total = 0

    for i in range(height):
        total += 2 ** i

    return total
```

예를 들어:

```text
height = 3
```

이면:

```text
2^0 + 2^1 + 2^2
= 1 + 2 + 4
= 7
```

---

# 3. Perfect가 아닌 경우

예를 들어:

```text
        1
      /   \
     2     3
    / \   /
   4   5 6
```

맨 왼쪽:

```text
1 → 2 → 4
```

맨 오른쪽:

```text
1 → 3
```

높이가 다르다.

즉:

```text
현재 subtree 전체는 Perfect가 아니다.
```

그러면 더 작은 subtree로 내려가서 똑같은 검사를 반복한다.

```python
return (
    1
    + self.countNodes(root.left)
    + self.countNodes(root.right)
)
```

여기서 `1`은 현재 `root`.

---

# 4. 방식 A 전체 코드

```python
class Solution:
    def countNodes(self, root: Optional[TreeNode]) -> int:

        def summation_nodes(height):
            total = 0

            for i in range(height):
                total += 2 ** i

            return total

        if not root:
            return 0

        # 현재 subtree의 맨 왼쪽 높이
        left_node = root
        left_height = 0

        while left_node:
            left_height += 1
            left_node = left_node.left

        # 현재 subtree의 맨 오른쪽 높이
        right_node = root
        right_height = 0

        while right_node:
            right_height += 1
            right_node = right_node.right

        # 현재 subtree 전체가 Perfect
        if left_height == right_height:
            return summation_nodes(left_height)

        # Perfect가 아니면
        # 양쪽 subtree에서 다시 똑같은 검사
        return (
            1
            + self.countNodes(root.left)
            + self.countNodes(root.right)
        )
```

---

# 5. 왜 양쪽 재귀인데 O(N)이 아닌가?

처음 보면:

```python
self.countNodes(root.left)
self.countNodes(root.right)
```

둘 다 호출하니까:

```text
모든 노드를 방문하는 것 아닌가?
→ O(N)?
```

라고 생각할 수 있다.

하지만 중요한 건 **각 recursive call에서도 다시 Perfect Tree인지 검사한다는 것**이다.

예를 들어:

```text
        1
      /   \
     2     3
    / \   /
   4   5 6
```

처음 `1`은 perfect가 아니다.

그래서:

```text
countNodes(2)
countNodes(3)
```

둘 다 호출한다.

그런데 `2`를 root로 하는 subtree:

```text
    2
   / \
  4   5
```

는 Perfect Tree다.

따라서:

```text
countNodes(2)
    ↓
Perfect 발견
    ↓
summation
    ↓
return
```

`4`, `5`까지 하나씩 재귀하지 않는다.

실제 흐름은 대략:

```text
countNodes(1)
│
├── countNodes(2)
│      └── PERFECT
│          → summation
│          → 바로 종료
│
└── countNodes(3)
       └── 아직 perfect가 아니면
           더 내려감
```

즉 **Perfect subtree를 통째로 pruning**한다.

---

# 6. 방식 A Complexity

Complete Binary Tree의 높이는:

```text
O(log N)
```

각 recursive call에서:

```text
왼쪽 끝 높이 측정
오른쪽 끝 높이 측정
```

을 하므로:

```text
O(log N)
```

그리고 불완전한 부분을 따라 내려가는 재귀 깊이 역시:

```text
O(log N)
```

따라서 전체:

```text
O(log N) × O(log N)

= O(log² N)
```

---

# 7. 내가 했던 디버깅 실수

이 코드:

```python
print(self.countNodes(left_node.left))
```

처음에는 그냥 디버깅용 `print`라고 생각했다.

하지만 이건 단순 출력이 아니다.

실제로:

```python
self.countNodes(left_node.left)
```

를 **한 번 더 실행**하고 그 결과를 출력한다.

즉:

```text
print(value)
```

는 그냥 출력이지만:

```text
print(self.countNodes(...))
```

는:

```text
countNodes 실행
+
print
```

이다.

따라서 Complexity Analyzer 입장에서는 **추가 recursive traversal**이 존재한다.

디버깅 코드도 시간복잡도 분석에 영향을 줄 수 있다는 점 주의.

# 8. 방식 B — 왼쪽/오른쪽 중 어느 Subtree가 Perfect인지 확인

두 번째 방식은 질문 자체가 다르다.

방식 A에서는:

```text
"현재 subtree 전체가 perfect인가?"
```

를 물었다.

방식 B에서는:

```text
"왼쪽 subtree와 오른쪽 subtree 중
어느 쪽이 perfect인가?"
```

를 판단한다.

---

# 9. 왜 Complete Binary Tree에서 이게 가능한가?

Complete Binary Tree의 핵심 조건:

```text
마지막 level은 반드시 왼쪽부터 채워진다.
```

따라서 현재 root를 기준으로 보면:

```text
왼쪽 subtree와 오른쪽 subtree 중
적어도 한쪽은 Perfect Tree라고 판단할 수 있다.
```

불완전한 노드들이 아무 곳에나 랜덤하게 존재할 수 없기 때문이다.

---

# 10. 방식 B에서 높이를 측정하는 방법

여기서는:

```text
root.left의 높이
vs
root.right의 높이
```

를 비교한다.

둘 다 **왼쪽 방향으로 내려가면서** 높이를 측정한다.

```python
def get_height(node):
    height = 0

    while node:
        height += 1
        node = node.left

    return height
```

왜 둘 다 왼쪽으로 가냐면:

```text
각 subtree 자체의 전체 높이
```

를 같은 기준으로 측정하려는 것이기 때문이다.

---

# 11. left_height == right_height

예를 들어:

```text
        1
      /   \
     2     3
    / \   /
   4   5 6
```

왼쪽 subtree 높이:

```text
2 → 4

height = 2
```

오른쪽 subtree 높이:

```text
3 → 6

height = 2
```

같다.

```text
left_height == right_height
```

Complete Tree는 왼쪽부터 채워지므로 이 경우:

```text
왼쪽 subtree가 Perfect Tree
```

라고 확정할 수 있다.

왼쪽:

```text
    2
   / \
  4   5
```

따라서 왼쪽 subtree는 재귀할 필요가 없다.

```python
left_count = summation_nodes(left_height)
```

그리고 오른쪽만 재귀:

```python
return (
    1
    + left_count
    + self.countNodes(root.right)
)
```

---

# 12. left_height != right_height

예를 들어:

```text
        1
      /   \
     2     3
    /
   4
```

왼쪽 subtree:

```text
2 → 4

height = 2
```

오른쪽 subtree:

```text
3

height = 1
```

높이가 다르다.

Complete Tree는 마지막 level을 왼쪽부터 채우기 때문에:

```text
왼쪽 subtree가 아직 채워지는 중
```

이라는 의미다.

따라서 반대쪽인:

```text
오른쪽 subtree
```

는 한 단계 낮은 Perfect Tree다.

그러므로 오른쪽은 바로 계산:

```python
right_count = summation_nodes(right_height)
```

왼쪽만 재귀:

```python
return (
    1
    + self.countNodes(root.left)
    + right_count
)
```

---

# 13. 방식 B 전체 코드

```python
class Solution:
    def countNodes(self, root: Optional[TreeNode]) -> int:

        def get_height(node):
            height = 0

            while node:
                height += 1
                node = node.left

            return height

        def summation_nodes(height):
            total = 0

            for i in range(height):
                total += 2 ** i

            return total

        if not root:
            return 0

        left_height = get_height(root.left)
        right_height = get_height(root.right)

        # 왼쪽 subtree가 Perfect
        if left_height == right_height:

            left_count = summation_nodes(left_height)

            return (
                1
                + left_count
                + self.countNodes(root.right)
            )

        # 오른쪽 subtree가 Perfect
        else:

            right_count = summation_nodes(right_height)

            return (
                1
                + self.countNodes(root.left)
                + right_count
            )
```

---

# 14. 방식 B Complexity

방식 B에서는 코드상으로 아예 재귀 호출이 하나뿐이다.

높이가 같으면:

```python
self.countNodes(root.right)
```

만 호출한다.

높이가 다르면:

```python
self.countNodes(root.left)
```

만 호출한다.

즉:

```text
한쪽 subtree
→ summation으로 통째로 계산

다른 한쪽 subtree
→ 재귀
```

구조다.

각 단계의 높이 측정:

```text
O(log N)
```

재귀 깊이:

```text
O(log N)
```

따라서:

```text
O(log² N)
```

# 18. 내가 처음 생각했던 Height 정의

내 원래 코드에서는:

```text
root = height 0
root.left = height 1
root.left.left = height 2
```

로 생각했다.

예:

```text
        1          height 0
      /   \
     2     3       height 1
    / \   / \
   4   5 6   7     height 2
```

따라서 전체 노드 수는:

```text
2^0 + 2^1 + 2^2
```

이므로:

```python
for i in range(height + 1):
    total += 2 ** i
```

가 된다.

반면 `root`부터 level 개수를 `1`로 세는 방식에서는:

```text
level count = 3
```

이므로:

```python
for i in range(height):
    total += 2 ** i
```

가 된다.

즉 이 차이는 알고리즘 차이가 아니라:

```text
height를 어떻게 정의했는가?
```

의 차이다.

# 진짜 핵심

두 방식 모두 결국 같은 최적화를 사용한다.

```text
Perfect Subtree를 발견한다.
        ↓
노드를 하나씩 방문하지 않는다.
        ↓
2^0 + 2^1 + ... 로 한 번에 계산한다.
        ↓
그 아래 재귀를 잘라낸다.
```

즉 핵심은:

> **Complete Binary Tree의 구조를 이용해서 Perfect Subtree를 찾아 통째로 계산하는 것.**

그리고 시간복잡도는:

```text
O(log² N)
```

이다.
