## Longest Consecutive Sequence — 왜 `for + while`인데 O(n)인가?

**핵심: 각 연속 구간은 `시작점`에서만 한 번 탐색되기 때문에, 모든 `while`의 총 탐색량을 합쳐도 O(n)이다.**

```python
if num - 1 not in hash_set:
```

이 조건이 중요한 이유는, 현재 숫자보다 1 작은 값이 없을 때만 해당 숫자를 **연속 구간의 시작점**으로 판단하기 때문이다.

예를 들어:

```text
hash_set = {1, 2, 3, 4, 5}
```

`1`은:

```text
1 - 1 = 0
0이 set에 없음
→ 시작점
```

이므로 `while`을 실행한다.

```text
1 → 2 → 3 → 4 → 5
```

하지만 이후:

```text
2 → 앞에 1이 있음 → skip
3 → 앞에 2가 있음 → skip
4 → 앞에 3이 있음 → skip
5 → 앞에 4가 있음 → skip
```

따라서 아래처럼 같은 구간을 반복해서 탐색하지 않는다.

```text
X 잘못된 경우

1 → 2 → 3 → 4 → 5
    2 → 3 → 4 → 5
        3 → 4 → 5
            4 → 5
```

실제로는:

```text
O 실제 동작

1 → 2 → 3 → 4 → 5

2 → skip
3 → skip
4 → skip
5 → skip
```

여러 연속 구간이 있어도 마찬가지다.

```text
{1,2,3,4, 10,11,12, 20,21}
```

실제 `while` 탐색:

```text
1  → 2  → 3  → 4
10 → 11 → 12
20 → 21
```

각 연속 구간은 서로 겹치지 않고 딱 한 번씩만 탐색된다.

따라서:

```text
바깥 for 전체 탐색      → O(n)
모든 while 탐색의 총합  → O(n)

전체
→ O(n) + O(n)
→ O(n)
```

### 면접용 한 문장

> `num - 1`이 없는 숫자에서만 탐색을 시작하기 때문에 각 consecutive sequence를 한 번만 훑게 되고, 모든 while 탐색의 총합이 O(n)이어서 전체 시간복잡도도 O(n)입니다.

### 더 짧게

> 시작점에서만 while을 돌기 때문에 같은 연속 구간을 중복 탐색하지 않아 전체가 O(n)입니다.
