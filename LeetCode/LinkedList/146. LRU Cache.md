# LRU Cache — 내가 실수한 부분들 정리

LeetCode 146. **LRU Cache**

## 핵심 구조

```text
HashMap
→ key로 Node를 O(1)에 찾기

Doubly Linked List
→ 사용 순서를 O(1)에 관리
```

---

# 1. HashMap에는 순서가 없다

처음 헷갈린 점:

```text
HashMap에 key -> Node로 저장하는데
HashMap은 순서가 없잖아?

그럼 누가 가장 최근이고
누가 가장 오래됐는지는 어떻게 알지?
```

정답:

> **순서는 HashMap이 아니라 Doubly Linked List가 관리한다.**

예:

```text
HashMap

1 -> node1
2 -> node2
3 -> node3
```

HashMap의 순서는 중요하지 않다.

실제 사용 순서는:

```text
HEAD <-> 2 <-> 1 <-> 3 <-> TAIL
         LRU           MRU
```

즉 역할이 다르다.

```text
HashMap
→ "이 key의 Node가 어디 있지?"

Doubly Linked List
→ "누가 가장 오래됐지?"
→ "누가 가장 최근이지?"
```

---

# 2. head / tail은 실제 데이터가 아니라 Dummy Node

처음에는:

```text
head = 가장 오래된 데이터
tail = 가장 최근 데이터
```

라고 생각하기 쉬웠다.

하지만 실제 구현에서는:

```text
HEAD <-> 실제 데이터들 <-> TAIL
```

처럼 `head`, `tail`을 **고정 Dummy Node**로 둔다.

예:

```text
HEAD <-> A <-> B <-> C <-> TAIL
         ↑               ↑
        LRU             MRU
```

실제 가장 오래된 Node:

```python
self.head.next_p
```

실제 가장 최근 Node:

```python
self.tail.prev_p
```

따라서:

```text
head 자체 = LRU ❌
head.next_p = LRU ✅

tail 자체 = MRU ❌
tail.prev_p = MRU ✅
```

---

# 3. 첫 번째 put만 따로 처리할 필요가 없다

처음에는:

```text
첫 번째 데이터만 head에 따로 넣어야 하나?
```

라고 생각했다.

하지만 Dummy Node를 사용하면 필요 없다.

초기 상태:

```text
HEAD <-> TAIL
```

첫 번째 `put(A)`를 할 때도 그냥 **tail 앞에 삽입**한다.

처음에는:

```python
self.tail.prev_p == self.head
```

이므로:

```text
old_latest = HEAD
```

가 된다.

그 상태에서 A를 삽입하면:

```text
HEAD <-> A <-> TAIL
```

자연스럽게:

```text
head.next_p = A
tail.prev_p = A
```

가 된다.

두 번째 `put(B)`도 똑같은 코드:

```text
HEAD <-> A <-> B <-> TAIL
```

즉:

> **항상 tail 바로 앞에 MRU Node를 넣는다.**

첫 번째 삽입만 따로 `if`문으로 처리할 필요가 없다.

# 4. Node의 prev / next는 처음에 None

잘못 생각했던 형태:

```python
class Node:
    def __init__(self, key, value):
        self.next_p = Node(0, 0)
        self.prev_p = Node(0, 0)
```

이렇게 하면:

```text
Node 생성
→ 내부에서 Node 생성
→ 그 Node 내부에서 또 Node 생성
→ ...
```

무한 재귀가 된다.

따라서:

```python
class Node:
    def __init__(self, key, value):
        self.key = key
        self.value = value
        self.next_p = None
        self.prev_p = None
```

으로 시작하고 실제 연결은 LRUCache에서 해준다.

# 5. defaultdict(Node)를 쓸 필요가 없다

처음:

```python
self.space = defaultdict(Node)
```

를 사용했다.

하지만 여기서는 없는 key에 접근했을 때 자동으로 Node를 만들 이유가 없다.

그냥:

```python
self.space = {}
```

를 사용하면 된다.

# 6. get()은 단순 조회가 아니다

LRU에서:

```python
get(key)
```

를 했다는 것은 해당 데이터를 **방금 사용했다**는 뜻이다.

따라서 해당 Node를 MRU 위치로 옮겨야 한다.

예:

```text
HEAD <-> A <-> B <-> C <-> TAIL
              ↑
            get(B)
```

먼저 B를 기존 위치에서 제거:

```text
HEAD <-> A <-> C <-> TAIL
```

그다음 tail 바로 앞으로 이동:

```text
HEAD <-> A <-> C <-> B <-> TAIL
                          ↑
                         MRU
```

즉:

```text
get
=
HashMap에서 Node 찾기
+
Linked List에서 MRU로 이동
```

---

# 7. Node를 제거할 때 양쪽 연결을 모두 수정해야 한다

예:

```text
A <-> B <-> C
```

B를 제거한다고 하자.

B 기준으로:

```python
target_prev = B.prev_p
target_next = B.next_p
```

즉:

```text
target_prev = A
target_next = C
```

B를 제거하려면:

```python
target_prev.next_p = target_next
target_next.prev_p = target_prev
```

즉:

```python
A.next_p = C
C.prev_p = A
```

둘 다 해야 한다.

결과:

```text
A <-> C
```

한쪽만 연결하면 Doubly Linked List가 깨진다.

---

# 8. Node를 MRU 위치에 붙일 때도 양쪽을 연결

현재:

```text
HEAD <-> A <-> C <-> TAIL
```

B를 가장 최근 위치로 넣고 싶다.

현재 MRU:

```python
old_prev = self.tail.prev_p
```

즉:

```text
old_prev = C
```

먼저 B 입장에서:

```python
B.prev_p = C
B.next_p = TAIL
```

그리고 주변 Node 입장에서:

```python
C.next_p = B
TAIL.prev_p = B
```

결과:

```text
HEAD <-> A <-> C <-> B <-> TAIL
```

따라서 삽입할 때는:

```text
1. target Node의 prev / next
2. 주변 Node들의 prev / next
```

둘 다 생각해야 한다.

---

# 9. 기존 key를 put할 때 새 Node를 만들면 안 된다

처음에는 `put()`마다:

```python
new_node = Node(key, value)
self.space[key] = new_node
```

를 하면 HashMap이 알아서 교체하니까 괜찮다고 생각했다.

하지만 HashMap과 Linked List는 별개다.

예:

```python
put(1, 10)
```

결과:

```text
HashMap:
1 -> nodeA

Linked List:
HEAD <-> nodeA <-> TAIL
```

다시:

```python
put(1, 20)
```

에서 새 `nodeB`를 만들어:

```python
self.space[1] = nodeB
```

하면 HashMap은:

```text
1 -> nodeB
```

로 정상적으로 교체된다.

하지만 Linked List에는 기존 `nodeA`가 자동으로 삭제되지 않는다.

잘못하면:

```text
HEAD <-> nodeA <-> nodeB <-> TAIL
```

가 된다.

따라서 기존 key라면 새 Node를 만드는 게 아니라:

```python
target_node = self.space[key]
target_node.value = value
```

로 기존 Node를 업데이트하고,

```text
기존 위치에서 제거
→ MRU 위치로 이동
```

해야 한다.

---

# 10. 가장 중요했던 실수 — 기존 key put의 순서

이게 실제로 Linked List를 깨뜨렸던 핵심 실수였다.

처음에는:

```python
old_prev = self.tail.prev_p
```

를 **target_node를 제거하기 전에** 저장했다.

그런데 target_node가 이미 MRU라면 문제가 된다.

예:

```text
HEAD <-> A <-> B <-> TAIL
                  ↑
             target_node
```

현재:

```python
self.tail.prev_p == B
```

이다.

그런데 먼저:

```python
old_prev = self.tail.prev_p
```

를 해버리면:

```text
old_prev = B
target_node = B
```

즉:

```python
old_prev is target_node
```

가 된다.

그 상태에서:

```python
target_node.prev_p = old_prev
old_prev.next_p = target_node
```

같은 작업을 하면 사실상:

```python
B.prev_p = B
B.next_p = B
```

처럼 자기 자신을 연결하는 구조가 생길 수 있다.

Linked List가 망가진다.

---

# 11. 올바른 순서

기존 Node를 MRU로 이동시킬 때는 반드시:

```text
1. 기존 Node를 먼저 뺀다.

2. 제거가 끝난 뒤 tail.prev를 확인한다.

3. target_node 입장에서 prev / next를 연결한다.

4. 주변 Node 입장에서 target_node를 연결한다.
```

코드:

```python
# 1. 기존 위치에서 제거

target_prev = target_node.prev_p
target_next = target_node.next_p

target_prev.next_p = target_next
target_next.prev_p = target_prev


# 2. 제거가 끝난 뒤 현재 MRU 확인

old_prev = self.tail.prev_p


# 3. target_node 입장

target_node.prev_p = old_prev
target_node.next_p = self.tail


# 4. 주변 Node 입장

old_prev.next_p = target_node
self.tail.prev_p = target_node
```

# 12. 내가 외우기로 한 순서

기존 Node를 MRU로 이동할 때:

```text
기존 거 먼저 뺀다
        ↓
tail 관점에서 old_prev 잡는다
        ↓
target_node 입장에서 prev / next 연결
        ↓
old_prev.next 연결
tail.prev 연결
```

더 짧게:

> **빼기 → tail 기준 잡기 → target 연결 → 주변 연결**

코드 순서로 외우면:

```python
# 1. 빼기
target_prev.next_p = target_next
target_next.prev_p = target_prev

# 2. tail 기준
old_prev = self.tail.prev_p

# 3. target 관점
target_node.prev_p = old_prev
target_node.next_p = self.tail

# 4. 주변 관점
old_prev.next_p = target_node
self.tail.prev_p = target_node
```

# 13. capacity 체크 시점

처음에는:

```python
if not self.space.get(key) and len(self.space) > self.capacity:
```

같은 방식으로 검사하려고 했다.

그런데 새 Node를 넣기 **전**이라면 아직 capacity를 초과하지 않았을 수 있다.

예:

```text
capacity = 2
현재 size = 2
```

새로운 `put(3, 3)`을 하기 직전에:

```python
len(self.space) > self.capacity
```

는:

```text
2 > 2
False
```

이다.

그래서 삭제되지 않는다.

따라서 더 자연스러운 순서는:

```text
새 Node 삽입
↓
HashMap에 저장
↓
capacity 초과 확인
↓
초과했다면 LRU 삭제
```

즉:

```python
self.space[key] = new_node

if len(self.space) > self.capacity:
    ...
```

# 14. capacity 초과 시 누구를 삭제하는가?

우리가 유지하는 구조:

```text
HEAD <-> LRU ... MRU <-> TAIL
```

따라서 가장 오래 사용하지 않은 실제 Node는 항상:

```python
self.head.next_p
```

이다.

예:

```text
HEAD <-> A <-> B <-> C <-> TAIL
         ↑               ↑
        LRU             MRU
```

capacity 초과 시:

```text
A 삭제
```

하면 된다.

# 15. eviction에서도 양방향 연결이 필요하다

현재:

```text
HEAD <-> A <-> B <-> TAIL
```

A를 삭제한다고 하자.

```python
old_next = self.head.next_p
new_next = old_next.next_p
```

즉:

```text
old_next = A
new_next = B
```

HEAD 입장:

```python
self.head.next_p = new_next
```

그리고 B 입장에서도:

```python
new_next.prev_p = self.head
```

를 해야 한다.

즉:

```python
self.head.next_p = new_next
new_next.prev_p = self.head
```

둘 다 필요하다.

결과:

```text
HEAD <-> B <-> TAIL
```

그리고 HashMap에서도:

```python
del self.space[old_next.key]
```

로 삭제해야 한다.

즉 eviction은:

```text
Linked List에서 삭제
+
HashMap에서도 삭제
```

두 작업이다.

# 16. get / put 전체 사고 흐름

## get(key)

```text
HashMap에서 Node 찾기
↓
없으면 -1
↓
기존 위치에서 제거
↓
tail 앞에 다시 삽입
↓
value 반환
```

## put(existing key)

```text
HashMap에서 기존 Node 찾기
↓

↓
기존 위치에서 제거
↓
tail 앞에 다시 삽입
```

Node 개수는 변하지 않는다.

## put(new key)

```text
새 Node 생성
↓
tail 앞에 삽입
↓
HashMap에 저장
↓
capacity 초과 확인
↓

```

# 17. 전체 자료구조 그림

```text
HashMap
--------------------------------

1 ────────→ Node(1)
2 ────────→ Node(2)
3 ────────→ Node(3)


Doubly Linked List
--------------------------------

HEAD <-> Node(2) <-> Node(1) <-> Node(3) <-> TAIL
         ↑                            ↑
        LRU                          MRU
```

HashMap:

```text
key → Node
```

를 통해 원하는 Node를 O(1)에 찾는다.

Doubly Linked List:

```text
LRU ↔ ... ↔ MRU
```

를 통해 사용 순서를 관리한다.

# 18. 최종 코드

```python
class Node:
    def __init__(self, key, value):
        self.key = key
        self.value = value
        self.next_p = None
        self.prev_p = None


class LRUCache:

    def __init__(self, capacity: int):
        self.capacity = capacity
        self.space = {}

        self.head = Node(0, 0)
        self.tail = Node(0, 0)

        self.head.next_p = self.tail
        self.tail.prev_p = self.head


    def get(self, key: int) -> int:

        target_node = self.space.get(key)

        if not target_node:
            return -1

        # 1. 기존 위치에서 제거
        target_prev = target_node.prev_p
        target_next = target_node.next_p

        target_prev.next_p = target_next
        target_next.prev_p = target_prev

        # 2. 제거 후 현재 MRU 확인
        old_prev = self.tail.prev_p

        # 3. target_node 입장
        target_node.prev_p = old_prev
        target_node.next_p = self.tail

        # 4. 주변 Node 입장
        old_prev.next_p = target_node
        self.tail.prev_p = target_node

        return target_node.value


    def put(self, key: int, value: int) -> None:

        # 기존 key
        if key in self.space:

            target_node = self.space[key]

            # value update
            target_node.value = value

            # 1. 기존 위치에서 제거
            target_prev = target_node.prev_p
            target_next = target_node.next_p

            target_prev.next_p = target_next
            target_next.prev_p = target_prev

            # 2. 제거 후 tail 기준 다시 잡기
            old_prev = self.tail.prev_p

            # 3. target_node 입장
            target_node.prev_p = old_prev
            target_node.next_p = self.tail

            # 4. 주변 Node 입장
            old_prev.next_p = target_node
            self.tail.prev_p = target_node


        # 새로운 key
        else:

            new_node = Node(key, value)

            old_latest = self.tail.prev_p

            # new_node 입장
            new_node.prev_p = old_latest
            new_node.next_p = self.tail

            # 주변 Node 입장
            old_latest.next_p = new_node
            self.tail.prev_p = new_node

            # HashMap
            self.space[key] = new_node


        # capacity 초과
        if len(self.space) > self.capacity:

            oldest = self.head.next_p
            new_oldest = oldest.next_p

            # Linked List에서 제거
            self.head.next_p = new_oldest
            new_oldest.prev_p = self.head

            # HashMap에서도 제거
            del self.space[oldest.key]
```

# 최종 암기

## 구조

```text
HEAD <-> LRU ... MRU <-> TAIL
```

```text
HashMap
→ Node 찾기

Doubly Linked List
→ 사용 순서 관리
```

## 기존 Node를 MRU로 이동

```text
1. 기존 거 먼저 뺀다

2. tail.prev 다시 확인

3. target_node의
   prev / next 연결

4. 주변 Node의
   next / prev 연결
```

한 줄:

> **빼기 → tail 기준 → target 연결 → 주변 연결**

## capacity 초과

```text
head.next_p
→ 가장 오래된 Node
→ Linked List에서 제거
→ HashMap에서도 제거
```

## 이번에 가장 중요했던 실수

> **target_node가 이미 MRU일 수도 있는데, 제거하기 전에 `tail.prev`를 저장하면 `old_prev == target_node`가 될 수 있다.**

그래서 반드시:

```text
먼저 기존 Node를 제거
↓
그 다음 tail.prev 확인
```

순서로 처리한다.
